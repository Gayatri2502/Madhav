# PREMIUM LANDING PAGE MASTERY CURRICULUM

## Philosophy
Landing pages are not templates. They are narratives. Every section exists to answer a specific question in the visitor's mind at a specific moment. Structure follows story, not convention.

---

## CORE PRINCIPLES

### Attention Control
- **Primary action**: One per viewport. No competing CTAs.
- **Visual weight**: Size, contrast, motion, isolation direct the eye.
- **Negative space**: Whitespace is not empty — it's active framing.

### Scroll Rhythm
- **Vary section height**: Short → tall → medium → short. Prevents monotony.
- **Alternate density**: Dense info → breathing room → interactive → proof.
- **Pacing**: Fast sections (hero, stats) → slow sections (case study, FAQ).

### Information Density
- **Progressive disclosure**: Headline → subhead → 3 bullets → expandable detail.
- **One concept per section**. Never mix problem + solution + features.

### Conversion Psychology
- **Anchoring**: Show value before price.
- **Social proof proximity**: Place testimonials near the claim they validate.
- **Risk reversal**: FAQ, guarantees, logos appear before final CTA.

## SECTION ANATOMY LIBRARY

Each section type has variants. Choose based on story position.

### 1. HERO
**Purpose**: Answer "What is this?" + "Why care?" in 3 seconds.

| Variant | When to Use | Structure |
|---------|-------------|-----------|
| **Statement** | Clear category, strong differentiator | Headline (value prop) + Subhead (mechanism) + Primary CTA + Visual proof |
| **Demonstration** | Product speaks louder than copy | Interactive demo / 3D viewer + Minimal copy + Ghost CTA |
| **Narrative** | Brand story IS the product | Scroll-triggered cinematic sequence + Chapter navigation |
| **Social-led** | Trust is the barrier | Logo cloud + Key metric + Headline + CTA |
| **Split** | Two distinct audiences | Left: Audience A value → CTA | Right: Audience B value → CTA |

**Rules**:
- Headline ≤ 10 words. Subhead ≤ 20 words.
- CTA label = outcome ("Start free trial" not "Submit").
- Visual must illustrate the headline claim.

---

### 2. NAVIGATION
**Purpose**: Orient, not decorate.

| Variant | When to Use |
|---------|-------------|
| **Minimal** | Single-page, scroll-only | Logo + CTA only |
| **Anchor** | Long page, distinct sections | Logo + 4-5 section links + CTA |
| **Mega** | Complex product, multiple audiences | Logo + Category dropdowns + Search + CTA |
| **Hidden** | Immersive experience | Hamburger only, reveals full-screen menu |

**Rules**:
- Sticky after first section.
- Active section indicator (scroll spy).
- Mobile: Bottom sheet, not drawer.

---

### 3. ANNOUNCEMENT BAR
**Purpose**: Urgency without interruption.

| Variant | When to Use |
|---------|-------------|
| **Static** | Permanent info (shipping, hours) |
| **Rotating** | 2-3 messages, auto-advance 5s |
| **Dismissible** | Campaign-specific, user can close |
| **Geotargeted** | Region-specific offers |

**Rules**:
- Never blocks hero headline.
- Max 1 line. Link or CTA, not both.
- Respect `prefers-reduced-motion` for rotation.

---

### 4. SOCIAL PROOF (Logo Cloud / Trust Bar)
**Purpose**: "Others like you trust us."

| Variant | When to Use |
|---------|-------------|
| **Logo Wall** | B2B, enterprise — 15-30 logos, grayscale, hover color |
| **Metric Row** | "10k+ teams", "99.9% uptime" — 3-4 key numbers |
| **Press Strip** | Media logos + "As seen in" |
| **User Avatars** | PLG, community — real faces, names, roles |

**Rules**:
- Logos: Same height, grayscale, `filter: grayscale(1) opacity(0.6)` → hover `opacity(1)`.
- Never fake logos. Use "Companies like..." if under NDA.

---

### 5. PROBLEM SECTION
**Purpose**: Agitate the pain. Visitor nods: "Yes, that's me."

| Variant | When to Use |
|---------|-------------|
| **Story Card** | Relatable scenario — illustration + "You've felt this" |
| **Data-Driven** | Industry stats — "73% of teams lose 10hrs/week to..." |
| **Comparison** | "Before [Product]" vs "After" — side-by-side pain points |
| **Interactive Calculator** | "Calculate your waste" — inputs → personalized cost |

**Rules**:
- No solution mention yet.
- 1 core problem, 3 symptoms max.
- Visual = pain visualization (cluttered desk, error screen, leaking bucket).

---

### 6. SOLUTION SECTION
**Purpose**: Reveal the "aha" — the new way.

| Variant | When to Use |
|---------|-------------|
| **Paradigm Shift** | "Stop doing X. Start doing Y." — Two-column flip |
| **Workflow Demo** | Step-by-step: Input → Magic → Output |
| **Architecture Diagram** | Technical buyers — system view with interactive nodes |
| **Video Walkthrough** | Founder narrates 60s demo, chapters scrubbable |

**Rules**:
- Directly mirrors Problem section structure.
- One core mechanism, not feature list.
- Visual = the mechanism in action.

---

### 7. FEATURE SECTIONS
**Purpose**: Prove the solution works. One feature = one outcome.

| Variant | When to Use |
|---------|-------------|
| **Outcome Cards** | 3-4 cards: Icon + Outcome headline + 1-sentence how |
| **Interactive Tabs** | 4-6 features, click → live preview updates |
| **Deep-Dive Accordion** | Complex features — headline → expand for specs/video |
| **Workflow Steps** | Linear process — Step 1, 2, 3 with micro-demo each |

**Rules**:
- Lead with **outcome**, not feature name.
- "Automated reports" → "Wake up to written updates."
- Max 4 features per page. Deeper → link to feature page.

---

### 8. PRODUCT SHOWCASE
**Purpose**: Let them see/feel the product.

| Variant | When to Use |
|---------|-------------|
| **Interactive Sandbox** | Real product, limited scope, no auth |
| **Guided Tour** | Hotspots on screenshot/video, click → tooltip + micro-demo |
| **3D/AR Viewer** | Physical product — rotate, explode, configure |
| **Code Playground** | Dev tools — live editor with instant result |
| **Split Screen** | Left: UI recording, Right: Narrated value per action |

**Rules**:
- Zero friction to try. No signup for sandbox.
- Record fallback video for no-JS / low-perf.
- "Powered by [Product]" watermark on exports.

---

### 9. INTERACTIVE DEMONSTRATIONS
**Purpose**: Prove claims by doing.

| Type | Example |
|------|---------|
| **Calculator** | ROI, savings, time |
| **Configurator** | Build your plan/stack |
| **Assessment** | "How mature is your X?" → personalized report |
| **Comparison Tool** | Us vs competitor — slider reveals difference |
| **Live Data** | Real-time dashboard with anon data |

**Rules**:
- Input → Instant output. No "submit" button.
- Shareable result URL.
- Capture email *after* value delivered.

---

### 10. STATISTICS / METRICS
**Purpose**: Quantify impact. Scannable proof.

| Variant | When to Use |
|---------|-------------|
| **Big Numbers** | 3-4 massive metrics, animated on scroll |
| **Benchmark Table** | Industry avg vs You vs With Us |
| **Trend Chart** | "Customers see 40% improvement in 30 days" |
| **Customer Quotes + Metric** | "Saved 20hrs/week" — Name, Role, Company |

**Rules**:
- Animate count-up on scroll (IntersectionObserver).
- Source every number (study, internal data, customer).
- Max 4 numbers. More = noise.

---

### 11. TESTIMONIALS
**Purpose**: Peer validation. "Someone like me succeeded."

| Variant | When to Use |
|---------|-------------|
| **Carousel** | 5-10 cards, auto-advance + manual, pause on hover |
| **Wall** | Grid of 9+ — filter by role/industry/size |
| **Video** | 30-60s clips, chapters, transcripts |
| **Case Study Teaser** | Card: Logo + Headline + Metric → Click → Full case study |
| **Tweet/Review Stream** | Live social proof, auto-refresh |

**Rules**:
- Photo + Name + Title + Company + Logo.
- Specific outcome > "Great product!"
- Video: Captions default on. Aspect ratio 16:9 or 9:16.

---

### 12. CASE STUDIES
**Purpose**: Full proof. Problem → Solution → Result.

| Variant | When to Use |
|---------|-------------|
| **Narrative Page** | Dedicated page: Challenge → Approach → Result → Quote |
| **Inline Accordion** | On landing page: Headline → Expand for full story |
| **Video Documentary** | 3-5 min, customer speaks, b-roll of product in use |
| **Interactive ROI** | "Company X saved $Y" — slider to see your estimate |

**Rules**:
- Structure: Context → Challenge → Why Us → Implementation → Results → Future.
- 3+ hard metrics. "3x faster" not "much faster."
- Customer speaks in their voice.

---

### 13. PRICING
**Purpose**: Reduce decision friction. Frame value.

| Variant | When to Use |
|---------|-------------|
| **Tiered Cards** | 3 plans: Starter / Pro / Enterprise — highlight "Best value" |
| **Usage-Based** | Slider: "X units/mo = $Y" — real-time calc |
| **Single Price** | One plan, simple product — "All features. $XX/mo." |
| **Contact Sales** | Enterprise only — "Let's design your plan" + form |

**Rules**:
- Annual default, monthly toggle. Show savings.
- Feature comparison table below cards (collapsible).
- FAQ inline: "What happens after trial?" "Cancel anytime?"
- Guarantee badge near price.

---

### 14. FAQ
**Purpose**: Eliminate final objections.

| Variant | When to Use |
|---------|-------------|
| **Accordion** | 6-10 questions, searchable, category tabs |
| **Categorized** | Billing, Technical, Security, Onboarding |
| **Video Answers** | Founder/CS answers each in 30s clip |
| **Interactive** | "Ask anything" → semantic search → answer |

**Rules**:
- Source questions from sales calls, support tickets.
- Answer in 2 sentences + link to docs.
- "Still have questions?" → Chat / Email / Calendly.

---

### 15. CTA SECTION (Final)
**Purpose**: One last ask. No distractions.

| Variant | When to Use |
|---------|-------------|
| **Centered Hero** | Headline + Subhead + Primary CTA + Ghost secondary |
| **Split** | Left: Value reminder + CTA | Right: Social proof (logos/quote) |
| **Form Inline** | Email capture + "Start free" — 1 field |
| **Calendar** | "Book demo" — embedded Calendly, 3 slots visible |

**Rules**:
- Same CTA label as hero (consistency).
- No navigation links. No footer here.
- Background = subtle pattern / gradient, not competing image.

---

### 16. FOOTER
**Purpose**: Utility, not afterthought.

| Zones | Content |
|-------|---------|
| **Primary** | Product, Solutions, Pricing, Resources, Company |
| **Secondary** | Legal, Privacy, Security, Cookies, Accessibility |
| **Social** | Twitter, LinkedIn, GitHub, Discord, YouTube |
| **Newsletter** | "Insights, not spam" + Email + Subscribe |
| **Brand** | Logo + Tagline + © Year |

**Rules**:
- 4-column max on desktop. Stack mobile.
- Newsletter: Double opt-in, preview link.
- Sitemap.xml linked for SEO.

## STORYTELLING STRUCTURES

Choose **one** per project. Do not mix.

### 1. Problem → Solution → Proof → Action
**Classic SaaS**. Linear, logical.
Hero → Problem → Solution → Features → Social Proof → Pricing → CTA

### 2. Vision → Demonstration → Trust → Access
**Innovative/Category-creating**. Show, don't tell.
Hero (demo) → How it works → Who uses it → Case studies → Get access

### 3. Pain → Agitation → Relief → Proof → Urgency
**High-consideration B2B**. Emotional.
Hero (pain) → Problem (agitate) → Solution (relief) → Case studies → Limited offer → CTA

### 4. Interactive Journey
**Product-led / Dev tools**. Play first.
Hero (sandbox) → Guided tour → Features → Community → Upgrade

### 5. Brand Narrative
**Premium/D2C/Brand-led**. Emotion > specs.
Hero (film) → Our story → Craft/Process → Product → Community → Shop

### 6. Comparison-Led
**Mature category, switching costs**.
Hero (vs competitor) → Comparison table → Migration proof → Switch offer → CTA

## ART DIRECTION SYSTEM

### Visual Language (Per Project)
Define **before** building:
1. **Color palette**: 1 primary, 1 accent, 3 neutrals, semantic (success/warn/error)
2. **Typography**: Display font (headlines) + UI font (body) — variable fonts
3. **Spacing scale**: 4px base → 4, 8, 12, 16, 24, 32, 48, 64, 96, 128
4. **Border radius**: Sharp (0), Rounded (8), Pill (9999) — pick 2
5. **Shadow system**: 3 levels (subtle, card, floating)
6. **Motion tokens**: Duration (fast/normal/slow), Easing (standard/emphasized/decelerate)
7. **Image treatment**: Duotone, B&W, full-color, illustrated, 3D render
8. **Icon style**: Outline, filled, duotone, animated — consistent weight

### Component Variants (Not One-Size)
Each component has **contextual variants**:
- Button: Primary, Secondary, Ghost, Destructive, Link — each in 3 sizes
- Card: Default, Elevated, Outlined, Interactive, Media-heavy
- Section: Default, Alternate (bg), Inverse (dark), Full-bleed

### Grid System
- **Desktop**: 12-col, 24px gutter, 1200px max
- **Tablet**: 8-col, 16px gutter
- **Mobile**: 4-col, 16px gutter (or 1-col stack)
- **Content width**: 640px (narrow), 960px (standard), 1200px (wide), full

## BUILD PROCESS

### Phase 1: Strategy (Before Design)
- [ ] Define visitor: Who, intent, awareness stage
- [ ] Define one primary action
- [ ] Choose storytelling structure
- [ ] Map sections to visitor questions
- [ ] Write all copy (headlines, subheads, CTAs) in a doc

### Phase 2: Visual Direction
- [ ] Moodboard: 3 reference sites (not competitors)
- [ ] Define visual language (tokens above)
- [ ] Sketch 3 hero concepts (mobile + desktop)
- [ ] Pick one → refine → design system in Figma

### Phase 3: Section Design
- [ ] Design each section in chosen structure
- [ ] Mobile-first, then desktop
- [ ] Define responsive behavior per section
- [ ] Annotate: animation, interaction, scroll behavior
- [ ] Review: Does each section answer its question?

### Phase 4: Development
- [ ] Set up design tokens in code (CSS variables / Tailwind config)
- [ ] Build component library (Button, Card, Section, Container)
- [ ] Implement sections in story order
- [ ] Add scroll animations (GSAP/ScrollTrigger)
- [ ] Integrate analytics (GA4 + custom events)

### Phase 5: Optimization
- [ ] Lighthouse 100/100/100/100
- [ ] Axe-core 0 violations
- [ ] Core Web Vitals: LCP < 2.5s, CLS = 0, INP < 200ms
- [ ] Cross-browser: Chrome, Firefox, Safari
- [ ] Device test: 320, 375, 768, 1024, 1440, 1920
- [ ] Reduced motion: Verify all animations respect preference
- [ ] A/B test: Hero headline, CTA label, section order
